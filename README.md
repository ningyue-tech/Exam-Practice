# 双科目在线练习：按科目独立白名单版

本包在本次上传的 `在线机考网站_双科目_GitHub发布包_重新开始清除标红版(1).zip` 上修改。
两门题库及原题答案完全保留。没有采用前一轮需要私有后端的短信登录版本。

## 首先说明边界

这是**纯静态的名单匹配/入口筛选版**，不是安全身份认证系统。

- 名单在公开的 `whitelist.js` 中；任何能访问网站的人都能下载它。姓名和完整手机号不是保密的。
- 没有真实短信验证码，不证明输入者持有该手机号。知道别人的姓名、手机号的人可能冒用。
- 所有校验、组卷、答案、分数和存储都在浏览器内，可通过改代码或浏览器存储绕过或修改。
- 不包含教师后台、云端成绩数据库、可靠的考试次数限制或防作弊能力。
- 页面上的“已验证”仅指**本科目的名单匹配成功**，不是短信验证、本人认证或服务端授权。
- 本包只包含示例名单，不包含用户提供的真实个人信息。不要把敏感真实人员名单放入公开静态文件。

需要保护真实名单、验证手机归属、限制次数和可信成绩入库时，必须使用私有后端进行鉴权及判分。
GitHub Pages 为静态资源托管，上传本包不会自动产生上述后台功能。

参考：
- GitHub Pages: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages
- OWASP（不得依赖客户端作为授权边界）: https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html

## 1. 只在一个文件中维护两份名单

只修改 `whitelist.js`：

```javascript
window.EXAM_WHITELISTS = {
  sessionHours: 12,

  // 汽车维修：仅用于汽车维修科目验证
  auto: [
    { name: "汽车测试", phone: "13800000001", enabled: true },
    { name: "双科测试", phone: "13800000003", enabled: true },
  ],

  // 商务营销：仅用于商务营销科目验证
  marketing: [
    { name: "营销测试", phone: "13800000002", enabled: true },
    { name: "双科测试", phone: "13800000003", enabled: true },
  ],
};
```

`auto` 与 `marketing` 的名字不能改；页面依照这两个科目编号选择数组。
每条记录将姓名和手机号绑在一起比较，不会将甲的姓名和乙的手机号拼接验证。
同一人在一科名单中，不会自动获得另一科资格；要考两科，分别添加到两个数组。

`name` 和 `phone` 必须用引号包裹。程序会去掉姓名首尾空白，规范全角字符；姓名内部空白不会删除。
手机号支持11位大陆手机号以及相应的 +86、0086、86 前缀，忽略空格和连接横线。
不是国际手机号通用登录系统。

`enabled: true` 为启用，`enabled: false` 为停用。该字段省略时默认启用；不要写成字符串 "false"。
删除一整条记录或停用，只影响它所在的那门科目。同科重复姓名手机号会提示配置错误。
保持每条记录后的英文逗号、各层方括号和大括号完整；任一科名单格式错误，整个配置会拒绝加载，不会默认放行。

`sessionHours` 为本地校验状态有效小时数，默认12，可设置大于0且不超过168的数字。
本地时间和本地状态可以被修改，这不是可信的考试时间或服务端会话控制。

## 3. 考生操作

打开 `index.html` → 选择科目 → 在 `login.html` 输入姓名和手机号 → 匹配本科目名单 → 进入该科目考试 → 开始新考试。

登录表单也可切换科目，系统会随选择改查对应名单。
汽车维修直接地址为 `auto-exam.html`；商务营销直接地址为 `marketing-exam.html`。
直接打开考试页、或通过 `?test=1` 打开功能验证入口，都会进行**本科目**的前端名单检查；未通过时不显示答题界面，而是显示前往验证的入口。
这只是界面控制，不会阻止浏览器下载原始HTML题库或恶意绕过。

首页会分别显示两科的本地验证状态。考试页可退出本科目，首页可退出全部科目验证。
当前标签页使用 `sessionStorage` 保存两科独立验证状态，不会自动建立另一科状态。
更换浏览器、标签页或设备时可能需要重新验证；本包不是跨设备账号系统。

## 4. 名单更新

首次发布后，日常添加或停用示例人员只需编辑 `whitelist.js`，无需改两门考试页面。
每次新打开页面会重新加载名单文件，并附带更新参数以减少旧缓存影响。
部署完成后刷新页面，新读取到的名单会重新核对旧验证状态；被删除或停用的人不再通过该科目检查。
**已打开的页面不实时轮询服务器，因此不保证即时撤销；以该页面实际加载的名单版本为准。**

## 5. 原有考试功能保留

- 两科题库：汽车维修796条、商务营销800条；本次对比确认原始题库数组文本逐字未改，不代表专业答案复核。
- 默认40道单选×1分＋20道多选×2分＋20道判断×1分＝80题、100分。
- 自定义题数合计必须仍为100分。随机组卷、模块权重、60分钟默认计时保持原样。
- 单选、判断点击单选框，多选点击复选框。
- 新考试题号使用默认颜色；检查未答或漏题交卷时标红；补答消红；取消多选全部选择后恢复未答提示。
- 重新开始清除上一场的红色标记、漏题面板和作答。
- 未答完时手动交卷会阻止提交并列出题号；到时按已答内容自动交卷，未答按0分。
- 保留全对评分、多选漏选半分设置、随机验证、答案回看、打印及文本成绩单。
- 新增姓名和脱敏手机号显示；成绩单包含当前考生姓名、脱敏手机号和科目。

## 6. 本地进度隔离

进度和成绩保存在浏览器 `localStorage` 中，按“姓名＋手机号＋科目＋是否功能验证”分别保存。
同科不同考生不会在正常页面流程中互相恢复记录；同一考生的两科和验证模式分别隔离。
不自动关联或迁移旧匿名版本的作答记录，避免把其他人的旧记录归给当前考生。
验证状态退出或过期不会删除当前考生的进度；同一考生重新匹配本科目可恢复。
离开和退出不会暂停倒计时。共享电脑上的浏览器存储不是私有成绩库，可被本机使用者查看或清除。

原来已使用 main / (root) 发布的站点，沿用该发布目录。所有网页链接和脚本采用相对路径，适配项目子目录。
移除不再使用的旧版无校验考试页面，避免用户误入；这不能将本身公开的题库变成私密资料。

发布后，用示例信息分别检查三种情况：汽车测试进汽车成功、汽车测试进商务失败、营销测试进商务成功。

本地预览可尝试解压后打开 `index.html`。某些浏览器对 file:// 的脚本或存储有额外限制，出现无法保持验证时，用本地HTTP服务打开。例如在解压目录运行：

```

```

然后访问 http://localhost:8080/ 。file:// 和真实GitHub Pages导航未在本环境实测。
