宁跃教育 · 名单维护说明（v2）

一、当前格式
whitelist.js 只保存名单校验值。每条记录由 salt、hash、enabled 三个字段组成，不含 name、phone 字段。
校验算法为 PBKDF2-SHA-256，迭代 600000 次；每个人在每个科目的记录使用独立随机盐。
网站用姓名和手机号的规范化输入计算并比对校验值。这是单向匹配，不是可解密还原姓名、手机号的密文。

二、维护命令
在仓库根目录打开终端，运行以下命令之一：

node scripts/manage-whitelist.mjs add auto
node scripts/manage-whitelist.mjs add marketing
node scripts/manage-whitelist.mjs add english
node scripts/manage-whitelist.mjs disable english
node scripts/manage-whitelist.mjs enable english

add：添加记录。
disable：停用记录。
enable：恢复启用。

三个操作均可使用以下科目参数：
auto：汽车科目组。
marketing：市场营销科目组。
english：英语。

姓名、手机号请按工具的交互提示输入，不要加在命令后面，不要粘贴到公开文件。工具自动更新本地 whitelist.js，检查后再提交发布。不要手工加入姓名或手机号字段，也不要将原始名单提交到仓库。

三、发布与已有进度
首次升级要一起发布六个 HTML 页面、access.js 和 whitelist.js，不能只替换名单文件。
以后日常添加、停用或启用人员，发布工具更新后的 whitelist.js 即可。
原有会话和答题进度沿用；名单停用后，对应科目访问资格失效。
为恢复同一考生的记录，本机浏览器仍保存本人姓名、手机号、验证状态和答题进度。普通练习与功能验证模式、不同考生及不同科目的记录分别隔离。

四、使用边界
输入只在当前浏览器校验，不发送短信，不验证号码归属，不提供服务端身份认证。
校验值随静态网页加载。随机盐及迭代计算可提高猜测成本，但不能保证无法破解，前端校验也可绕过。

需要真实安全身份认证或集中管理成绩时，应使用服务端方案。
